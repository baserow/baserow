# Application builder template regression testing

## Summary

When the application builder team is making substantial changes to the element hierarchy, it is useful to have a baseline to work from as a source of truth.

The system described below ensures that when a product engineer refactors the page and/or element hierarchy, they can avoid introducing regressions. 

This system captures the element tree of every builder template as a committed snapshot. Running it on a feature branch shows exactly which templates (if any) produce a different structure after the refactor.

## How to update snapshots

Snapshots live in `web-frontend/test/unit/builder/__snapshots__/templates/` — one `.snap` file per template. They are committed to the repo as the source of truth.

The element trees are generated by a Django management command (`export_builder_template_trees`) that installs each builder template into a temporary workspace and reads the resulting element hierarchy directly from the database. No web server is required — only a running database with templates synced.

**When a new template is added**, only that template's fixture needs generating — existing templates are skipped automatically:

```bash
just b manage sync_templates
just b manage export_builder_template_trees
just f yarn test:core builderTemplateRegression --run --update
git add web-frontend/test/unit/builder/__snapshots__/templates/
git commit -m "chore: add regression snapshot for <template-slug>"
```

**When an existing template is intentionally modified**, sync the updated template and force regeneration:

```bash
just b manage sync_templates
rm web-frontend/test/unit/builder/fixtures/templates/<slug>.json
just b manage export_builder_template_trees
just f yarn test:core builderTemplateRegression --run --update
git add web-frontend/test/unit/builder/__snapshots__/templates/<slug>.snap
git commit -m "chore: update regression snapshot for <slug>"
```

To force regeneration of all templates at once:

```bash
just b manage export_builder_template_trees --force
```

**To verify a feature branch hasn't introduced regressions**, regenerate the fixtures from your branch first, then compare against the committed snapshots:

```bash
just b manage sync_templates
just b manage export_builder_template_trees --force
just f yarn test:core builderTemplateRegression --run
```

The fixtures are gitignored, so they must be regenerated on each branch before the Vitest run is meaningful. A failure means the element tree for that template differs from the committed baseline. The diff shows exactly what changed.
